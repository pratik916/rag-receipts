System architecture — v1

Three planes: ingestion (left), query serving (center), evaluation (right). Dashed = v1.1 graph slot.

INGESTION PLANE
Corpus loaders
NQ + MuSiQue/2Wiki slices · BYO docs (PDF/MD/HTML)
↓
Chunker
LlamaIndex sentence-window / by-title
↓
Contextualizer
voyage-context-3 contextualized chunk embeddings
(alt backend: Claude contextual prefixes + voyage-3)
↓
Qdrant
dense vectors
BM25 index
bm25s, in-process
Graph index (v1.1)
HippoRAG-2-style triples + PPR
QUERY PLANE (FastAPI + LangGraph)
Router — Claude classifies query complexity
emits route + confidence into the trace
System-1 fast path
hybrid retrieve → RRF → Cohere rerank → Claude answer + citations
System-2 agentic loop
decompose → per-hop retrieve (same core) → CRAG-style sufficiency grading → re-query / correct → synthesize
↓
Shared retrieval core
one code path used by both routes AND the eval harness — receipts measure exactly what serves queries
↓
Trace store
every hop, score, prompt, token count → Playground trace viewer
EVAL PLANE
Ablation runner
config matrix (components on/off) × benchmark slice, run as background jobs
↓
Metrics
Recall@5 / MRR@3 vs gold passages · RAGAS faithfulness + answer relevancy · latency · $ cost
↓
receipts.json
versioned, committed — each receipt links the published delta it reproduces
↓
Ablation Lab UI
charts + "ours vs published" comparison
Frontend — Next.js app: Playground (query box, route badge, hop-by-hop trace, chunk scores, cited answer) · Ablation Lab (receipts charts) · Corpora (benchmark slices + BYO ingest with progress).
Packaging — docker compose: api + web + qdrant. One .env for the three vendor keys.
